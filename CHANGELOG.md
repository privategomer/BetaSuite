# Changelog

This fork's releases. Versions follow [semantic versioning](https://semver.org/).

## Unreleased
### Added

- `console_palette` (`'standard'`): `'deuteranopia'` / `'protanopia'` (no red against green) and `'monochrome'` (weight only) for the terminal colors, and lines are now colored by run phase (detect, structure, reverse, render, prep), including the in-place progress line
- `console_color` (`'auto'`): the terminal view colors each file's `processing` line (bold cyan) and `done` line (bold green, numbers in green), `skipping` dim, `failed` bold red, warnings yellow and errors red. The log file never carries color codes. `'auto'` colors only a terminal and honours `NO_COLOR` and `FORCE_COLOR`; `'always'` and `'never'` force it either way. The tools' own loggers follow the same rule

### Changed

- Local config replaces the machine config. Your own settings now go in `betaconfig_local.py`, beside `betaconfig.py` and ignored by git: copy a setting in to change it, delete the line to go back. `betaconfig.py` is the shipped defaults only and is never edited. Any setting `betaconfig.py` has may be set there, tuning included; the hardware-only list and the refusal of tuning settings are gone. An unknown name is a validation error naming the file and line, with the closest real name. Dicts merge key by key at every depth; lists, plain values and a complete censor style (a dict with `'type'`) replace whole; a merged key `betaconfig.py`'s dict lacks is a warning. Precedence: `betaconfig.py < betaconfig_local.py < command-line flags`. Every validated run logs `local overrides active: ...` at info, and each stats row lists them in `local_overrides`. `BETASUITE_LOCAL_CONFIG` names another file, or `none` to ignore it. See CONFIG_REFERENCE.md, "Local config"
- `tools/setup/local_config.py` replaces `machine_config.py` (which still works and forwards with a one-line note): `show` lists every setting with its value and source (default, local or CLI, with betatv.py's flags applied on top when given), `init` creates a header-only file, `set` validates before writing and keeps comments, `unset` deletes the line, `check`, `migrate` and `setup`. `tune_machine.sh`, `setup.sh` and `setup.ps1` write to it under a `hardware (written by tune_machine)` header
- `console_palette` in `betaconfig.py` is `'standard'`, as documented above; the file had shipped a personal `'deuteranopia'`
- Upgrade: `../resources/betaconfig_machine.py` is no longer read, so its settings stop applying until moved. Validation, `local_config.py show` / `check` and `verify_env.py` warn with the command until you run `python tools/setup/local_config.py migrate`, which copies each setting that differs from `betaconfig.py` into `betaconfig_local.py`, keeps any local value already set, and renames the old file to `betaconfig_machine.py.migrated`. Cache cost: none from the upgrade itself once migrated, since the merged values are the same as before; a setting that does not apply between the upgrade and the migration (an encoder, say) gives that run new encode keys, and those outputs are rendered again once
- `betaconfig.py` ships portable defaults: `nudenet_v3` `model_variant` is `'320n'` (was `'640m'`, the optional 103 MB manual download), `gpu_enabled` is `0` (was `1`), `log_level` is `'info'` (was `'debug'`), and the `exposed_vulva` and `exposed_breast` styles carry no stickers, since no sticker images ship and there is no licence to ship any (an empty sticker folder renders a solid bar). The remaining weights are rescaled in proportion: `exposed_vulva` blur only, `exposed_breast` blur 24.4, mosaic 30.5, hex 30.5, bar 14.6. Most per-label tuning was measured at 640m and is unchanged, so at 320n it is a starting point. Upgrade cost: an install that relied on the old values gets new detection keys (320n) and new censor keys (styles), so it detects and renders again; to keep them, set them in `betaconfig_local.py` (`detector_backend = { 'nudenet_v3': { 'model_variant': '640m' } }`, `gpu_enabled = 1`, `log_level = 'debug'`, and the full style lists with sticker entries), which keeps every key and finished output
- `tools/bench/tune_machine.sh` proposes `gpu_enabled`: 1 when onnxruntime has CUDAExecutionProvider and nvidia-smi sees a GPU, 0 when either is missing. Decided from what is installed, not timed; the batch-size, prefetch and render stages then measure with it
- Settings the code read with a built-in fallback are now listed in `betaconfig.py`, at that same value, so they can be set in `betaconfig_local.py`: `blur_edge_margin`, `default_confirm_score`, `default_geometry_action`, `default_size_smoothing` (`None` keeps a third of `position_smoothing`), `force_structure_profile`, `profile_by_path_pattern` and the four `render_motion_*` settings. Upgrade cost: none; the three `default_*` ones enter the censor key only once changed, so every key stays the same
- Nothing is censored until you choose: `items_to_censor` ships `[]`, and reverse mode ships no windows with person windows off, since what gets censored and what shows through are taste. `betatv.py`, `betastare.py` and `betavision-censor.py` stop before any detection when a run would change no frame (exit 0, a warning naming `local_config.py set "items_to_censor=[...]"`), instead of spending the full detect and render time on a copy of the input. CONFIG_REFERENCE.md has an example local config: the one line for basic censoring, and one user's whole file as a template. Upgrade cost: a config that relied on the shipped labels or windows censors nothing until they are set in `betaconfig_local.py` (`items_to_censor = [ 'exposed_vulva', 'exposed_breast' ]` restores normal mode exactly, keeping every key and finished output); a reverse-mode config gets new censor keys if its windows differ from the old four, so reverse outputs render again
- The four unsafe suppression pairs (`exposed_vulva` suppressed by `exposed_penis`, `face_femme`, `exposed_buttocks` or `exposed_feet`, where both parts are really there and a rule removes the censor when it is needed) are built in (`betautils_detector.UNSAFE_SUPPRESSION_PAIRS`, each with its reason) and never proposed by `betabench suppression`, the suppression A/B or `derive_suppression_rules.py`, for any backend or user. `class_suppression_refused` ships `[]` and holds only your own pairs, added to them. A hand-written rule for one of them warns at validation. `retinanet_v2` shipped two of them and they are removed. Upgrade cost: `retinanet_v2` censor keys change, so its outputs render again once; `nudenet_v3` is unchanged
- No tool writes `betaconfig.py`. `auto_tune.py --apply` writes accepted values to `betaconfig_local.py` through the same editor as `local_config.py set` (comment `set by auto_tune <run>`, a backup of the file in the run folder), applies them to the running config, and undoes a write the resolver does not read back or that fails validation; its regex editor for `betaconfig.py` is gone. Before, a local line for the same setting hid the edit, the read-back failed and the value could not be applied. `ab_compare.sh decide` and `derive_suppression_rules.py` print a `local_config.py set` command instead of lines to paste into `betaconfig.py`. `run_bar_smoothing_test.py` gives each variant its own local config through `BETASUITE_LOCAL_CONFIG` (saved beside its result) instead of rewriting `betaconfig.py` and restoring it, so an interrupted run can no longer leave the shipped file on a test variant. The `set by auto_tune` comments are gone from `betaconfig.py`
- A new key merged from the local config is warned about only where validation does not check that block's keys (a backend's own block, `person_backend`). Inside `item_overrides`, reverse `windows` and `overrides`, a misspelt key is already an error, and a new label or per-label key, which the tuners write, warned on every run

### Fixed

- Validation stopped every run of a config that censors nothing: the shipped `covered_vulva` promotion targets `exposed_vulva`, and a target that is not rendered was an error. It is an error only while the source label is rendered, the one case where promoted boxes lose their censor
- `derive_suppression_rules.py` proposed refused pairs, including the unsafe ones, so its dict could hand back a rule the A/B would never offer
- `--backend retinanet_v2` stopped at validation on the shipped config: `profile_by_source_dir` names `scene`, `compilation`, `quick_cut` and `split_screen`, and `retinanet_v2` had no profiles. It now has those four with timing only (`quick_cut`'s threshold and 18fps sampling, the two manual ones, an empty `scene`). Upgrade cost: `retinanet_v2` censor keys change, so its outputs render again once; `nudenet_v3` keys are unchanged
- Validation checks `default_geometry_action`, `default_confirm_score` and `default_size_smoothing`. A bad value there applied to every label without one of its own and was never reported
- The folder convention (`profile_by_source_dir`) now reads a video's folder under `video_path_source_backup` (`resources/source/`) as well as `video_path_uncensored`, trying the working tree first. A finished video moved from `uncensored_vids/scene/` to `source/scene/` used to read as outside the tree in every replay (the analysis hub's jitter, track-break, style-flicker and cut-burst steps, `auto_tune`, the A/B tools), so it fell through to measured selection and was analyzed under a different profile than the one that rendered it, with no message. An explicit `uncensored_root` is still the only root tried, which `betabench structure` relies on

## 1.4.0 (2026-11-10)
### Added

- `betabench structure`: the compilation boundary moves from 50% to 37.5% of runtime in sub-10s shots, the middle of the one empty stretch in a survey of 176 whole-file scans (nothing between 34.6% and 40.6%), which sorts four files that were sitting in `scene/` or recommended there into `compilation/`. New `<30s` column and `sub30_shot_fraction` in `results.json`: the share of runtime in sub-30s shots, there to be read and not used to decide, because on that survey it did not separate compilations from scenes (79 scene-folder files ran 0% to 100%, 23 of them at 67% or more). The bench's boundary is advisory; the app's profile selection and censor key are unchanged
- `betabench structure --write-move-script`: moves the safety rules hold back (a manual folder's judgment, a lower sample rate, slice-only timing, an unmapped folder) are now in the script too, in a HELD BACK section with the reason on each, instead of only in the log. A plain run reports them and moves nothing; `moves.sh --include-held-back` makes them, still with `mv -n`. The script is written when only held-back moves exist, and `structure_survey.sh` names the flag. The script now finds the videos relative to its own folder (resolved when it runs), so it works from any directory and belongs beside the survey logs under `output/`, where `structure_survey.sh` and `run_all_analysis.sh` write it; it no longer has to be copied into the source tree and removed afterwards. Before moving anything it checks that each source tree is where it expects and stops with a message and exit status 3 if the script was copied somewhere those paths no longer reach, instead of reporting every file as not found. `move_one` checks the target itself, so a skipped move reads "skip (target exists)" on GNU coreutils 9.2 and later, where `mv -n` exits nonzero for it and the script printed FAILED
- Machine config: `../resources/betaconfig_machine.py` holds this computer's hardware settings, outside the repo, so a pull or a branch switch never touches them and one machine's tuning never becomes every checkout's default. A setting there replaces the same one in `betaconfig.py` on that machine; command-line flags still win. It may set only hardware settings (`gpu_enabled`, `cuda_device_id`, `nn_batch_size` and person `batch_size` per backend, `detection_prefetch_frames`, `render_workers`, `render_decode_threads`, `render_worker_mb_per_megapixel`, `render_memory_reserve_mb`, `render_chunk_seconds`, `encode_video_codec`, `encode_preset`, `encode_crf`, `preview_encode_preset`, `structure_scan_workers`, the `vision_cap_*` screen region); a tuning setting there is refused by name, because per-machine detection settings would make two machines' output disagree with nothing in the log to say why. Plain `name = value` lines, read and never executed. A line that is not allowed is skipped, printed, and then stops `betatv.py` at validation with the file's name; every validated run logs which file applied what. `BETASUITE_MACHINE_CONFIG` points at another file, or `none` to ignore it (the test suite does, so it sees the repo's defaults on any machine)
- `tools/setup/machine_config.py`: `show` (every hardware setting, its value and whether it comes from the machine config or `betaconfig.py`), `init` (a new file with every setting commented out at `betaconfig.py`'s value), `set NAME=VALUE` (checked the way `betatv.py` would before anything is written; nested ones as `detector_backend.nudenet_v3.nn_batch_size=8`), `unset`, `check`. Edits keep a person's own lines and comments
- `tools/bench/tune_machine.sh` (`tune_machine.py`): measures this machine and offers to write the results to its machine config. Inventory (CPU, memory, GPU and driver, hardware encoders, onnxruntime providers, OpenCV's decode support), detection batch size with a check that the detections do not change with the batch, frames decoded ahead during detection, render worker count by decoder threads with memory sampled per worker, `betabench encode`, and structure-scan workers. A setting is proposed only when it beats the current one by more than the larger of 3% and the stage's own run-to-run spread (detection re-times the current batch size, prefetch re-times none ahead); a near tie goes to the cheaper setting. `render_workers` is only ever raised: it is measured on the file with the most pixels but applies to every file, and the memory cap already limits large frames. Render memory is reported by side (Python's decoders and frames, the ffmpeg encoders). Asks before starting when the machine looks busy (a betatv run, load, a busy GPU) and before writing anything, and Ctrl+C at that prompt prints the command to write the proposal later; reads no cache and writes nothing else
- `detection_prefetch_frames` (0, off): detection can decode frames on a second thread while the model runs, so a sampled frame would cost the slower of decode and inference instead of both. Same frames in the same order, same detections; a test holds both to the plain path. The person-segmentation pass uses it too. Off by default because the first real measurement (RTX 3070 Laptop, 16 threads) found no gain at 4K or 1080p, within run-to-run noise; `tune_machine.sh` proposes it where it measures one
- `render_decode_threads` (None): decoder threads per render worker. OpenCV gives every capture one decoder thread per core, so 8 workers on 16 cores ran 128 decoder threads, each holding a decoded frame in flight; 0 shares the cores out between workers instead, a number sets it. None keeps the old behaviour until `tune_machine.sh` has measured a machine
- `structure_scan_workers` (0 = one per core, at most 4): `betabench structure-scan`'s worker count from config. `betabench concurrency` names the setting to change

- `tools/bench/profile.sh`: where any Python tool's time and memory go, as flame graphs. py-spy samples the CPU from outside the process (`cpu_flamegraph.svg`), memray records every allocation and opens its flame graph at the moment of peak memory (`memory_flamegraph.html`, `memory_stats.txt`); `PROFILE=cpu|memory|both` (both runs the tool once under each), `PROFILE_PID=<pid>` samples a step already running for `PROFILE_SECONDS` (30). An unprofiled run's wall time and peak memory go beside them (`meter.json`). Without the packages it falls back to cProfile (`cpu_top.txt`) and tracemalloc (`tools/lib/trace_memory.py`, `memory_top_lines.txt`: the top lines at the peak). Output in `../output/benchmarks/profile_<timestamp>_<tool>/`. `requirements-dev.txt` gains memray (not on Windows, which has no build) and py-spy, and the script offers to install them into the project's Python when they are missing (with uv when that venv has no pip, as setup's uv-made venv does not; never when unattended)
- `run_all_analysis.sh` meters every step (`tools/lib/step_meter.py`): wall time and peak memory per step in the summary and in `<step>.meter.json` beside its log, and an exit 137 is reported as a kill for memory with the peak the step had reached. A parallel step starts only when its expected peak fits beside the steps already running, within 85% of the memory free when the batch starts (`--memory-budget MB` or `BETASUITE_ANALYSIS_MEMORY_MB` to set it; `--jobs` still caps the count). Expected peak is the step's peak in the newest earlier run that recorded one, plus 25%, or with no history 300 MB plus 8 times the detection caches' size on disk; a step bigger than the budget runs alone. Each decision is in the run's `admission.log`. Where the system does not report free memory (macOS, native Windows) only `--jobs` applies

- Reverse mode (`reverse` block, `--reverse on/off`): while a trigger is live the whole frame gets a frame style (blur `triple_box` strength 7 by default, dimmed 40% with the frame style's `dim`, 0 to 1, which darkens only the frame layer and fades with it; `gaussian` and `hex` are rejected as too slow), except **windows**, labels left uncensored (`{'type': 'show'}`; shipped: `face_femme`, `face_masc`, `exposed_chest`, `exposed_penis`, each with area safety 1.0, twice the detection's width and height, as an ellipse with feather 0.3 that keeps the whole detection clear), and **censored labels** (`reverse['censor']['labels']`, `None` meaning `items_to_censor`), which keep their normal-mode styles and shapes, with reverse-only `overrides` for any key. A label is one or the other; a window with a censor style is a validation error. The trigger fires on detections of its labels (`None`: every censored label, so a face never triggers) after dedup, promotion, geometry and suppression but before each label's own `min_prob`, each held from one sample interval before to `hold_seconds` after, and also wherever a censored label's box is on screen, so a censored object never sits in a clear frame. The fade finishes before the target appears. `empty_frame` `'passthrough'` (default) leaves untriggered frames clear at no extra cost; `'obscure'` obscures every frame. Windows inherit every tuning key from every tier and profile, never a look key; reverse-only keys win over all of them. Censored labels are rendered from the original and blended once, so a feathered edge never shows the source, and inside their shape they match normal mode pixel for pixel. The censor key covers the block and each rendered label's resolved settings only while it is on, so existing renders keep their names; reverse outputs end in `-reverse`. betastare obscures a still on a trigger detection or a censored box; betavision refuses to start with it on. Known limitation: a sticker's transparent parts and a bar thinner than its box show the original (validation warns). The run's stats gain `reverse_trigger_detections`, `reverse_censored_boxes`, `reverse_trigger_intervals` and `reverse_triggered_seconds`
- Reverse mode person windows (`reverse['person_windows']`, on in the shipped config): whole male bodies left uncensored. A person-segmentation pass outlines every person in each sampled frame, in a thread alongside detection and cached beside the detection caches; a detection (at or above `evidence_min_prob`, after dedup, promotion, geometry and suppression) votes for the one person whose outline holds its centre (inside two overlapping outlines, for neither), and a track is male with a male vote and more male than female votes. Male evidence is `face_masc` and `exposed_chest`; `exposed_penis` is not, since in penetration it sits inside the partner's outline and outvoted her own face. People are linked across samples by box overlap, so a man stays a man while his face is turned away. Every outline that isn't shown, a woman's or anyone not attributed, is cut out of the men's, so she stays obscured where she overlaps him; when the model merges two bodies into one outline, a female detection inside it that no separate outline accounts for hides that outline at that sample. Between samples the window is the overlap of both samples' outlines. Censored labels still win where they overlap. The pass checkpoints like detection (every `detection_checkpoint_frames` samples, on Ctrl-C, and when the file fails) and resumes from there. The person model is in the censor key while person windows are on; with them on and the model missing, startup refuses with the fix. betastare does the same per still. Stats gain `reverse_person_masks` and `reverse_male_person_samples`
- `tools/analysis/analyze_person_windows.py`, a `run_all_analysis.sh` step (`person_windows.json`): replays person-window attribution from a reverse run's person caches and reports frames with a man shown, every person outline by attribution (shown, female evidence, no evidence, mixed votes, merged-outline backstop), people tracked, where each evidence detection's centre fell (one outline, two or more, none), and the videos with the most unattributed person-seconds. `male_people_by_time` takes an optional `tally` for it; the windows are the same with or without
- `person_backend` and `segmenters/`: person-segmentation backends shaped like `detector_backend` (`selected`, a block per backend, `model_variant`, `BETASUITE_PERSON_BACKEND_OVERRIDE` / `_VARIANT_OVERRIDE`). `yolo11_seg` (Ultralytics YOLO11-seg `n`/`s`/`m`, default `s`, AGPL-3.0) runs as ONNX through onnxruntime, letterboxed only to the next multiple of 32 so a 16:9 frame runs at 640x384; its decoder matches Ultralytics' predictor (same people and scores, box IoU 1.00, mask IoU 0.98 to 0.997 on its sample images)
- `rf_detr_seg`, the second person backend: Roboflow RF-DETR-Seg `nano`/`small`/`medium` (default `small`, Apache-2.0 for the code and every size), run as ONNX through onnxruntime to the same contract as `yolo11_seg`, so reverse mode's person windows work unchanged with either. Settings are `model_variant`, `model_path`, `min_prob` (0.35) and `batch_size` (4). The export fixes a square picture size per variant (312, 384, 432), read from the model file; setting `picture_size` is a validation error. Frames are stretched to the square, Roboflow's own convention: on real 16:9 footage a letterbox found fewer people and drew worse outlines at every size. Person is the export's class column 1 (COCO's sparse ids); no NMS, since each person is one query, and nested boxes near the floor are kept rather than risk merging away a second person. Measured on the same frames: on a GPU small is about a quarter faster than YOLO11s and nano close to half, on a CPU both are slower (nano 1.5x, small 2.1x), and on the people both families' biggest models agree on, small finds 98.8% against YOLO11s' 98.2%. The shipped backend stays `yolo11_seg`. Roboflow's large, xlarge and 2xlarge are left out: large found no more people than small at 1.9x its GPU time
- Setup exports the RF-DETR-Seg models beside YOLO11-seg: `fetch_models.py` downloads Roboflow's `.pth` releases (pinned by sha256; Roboflow's own md5s match) and exports them in the same throwaway environment, which gains `rfdetr`. Exports run offline from the checked file. About 125 MB per size; `verify_env.py` loads them when present
- Setup asks which person backends to export, one or more: `yolo11_seg` (default, about 143 MB for its three sizes), `rf_detr_seg` (about 375 MB), both, or none, and exports every size of each chosen one. The throwaway export environment installs only the chosen backends' packages, so a YOLO-only install no longer downloads `rfdetr`. Enter, `--yes` or no terminal takes the default, which also finishes any backend already partly exported. `--person-backends LIST` (`-PersonBackends`) on setup and `fetch_models.py` answers it ahead (`all`, `none`, or names); an unknown name stops `fetch_models.py` with the valid choices. The question appears only while a model is missing. Upgrade cost: none; models already present are kept and checked, nothing regenerates. An unattended install now leaves out RF-DETR-Seg, where before it exported all six; choose `rf_detr_seg` to get it
- `betabench persons --person-variants` applies to every backend and each skips the names that are not its sizes, so `s small` measures YOLO11s beside RF-DETR-Seg small
- Setup exports the YOLO11-seg models: `fetch_models.py` downloads Ultralytics' `.pt` releases (pinned by hash) and exports them to ONNX in a throwaway environment (ultralytics plus CPU-only PyTorch) that is deleted afterwards, so the runtime `.venv` never gets PyTorch. `--no-export` skips it, `--uv` names the uv setup installed, `BETASUITE_EXPORT_TORCH_INDEX` points at a mirror. `verify_env.py` loads the person models when present
- `betabench persons`: each person backend and size on real frames, ms per frame per batch size, people found, and preview images with the outlines drawn; unimplemented backends are listed as skipped. `run_all_analysis.sh --with-persons` runs it as a timing step (also part of `--with-timing`)
- `setup.sh` and `setup.ps1` offer the latest release. In a git checkout the first step fetches tags and offers to switch to the newest `vX.Y.Z` tag (pre-releases skipped), then restarts setup from that release's own script with the original arguments, so a fresh clone of main installs released code. Uncommitted tracked changes: warns and stays. Logs when the checkout is ahead of the tag. `--no-release-check` (`-NoReleaseCheck`) or `BETASUITE_RELEASE_CHECKED=1` skips it. The setup log gains a `version:` line. `SETUP.md` covers the step, the flag, updating, and the manual commands
- `tools/maintenance/cleanup_output.sh` (`cleanup_output.py`): frees disk under `../output` by category, showing the plan and asking before each: renders of decided A/B rounds, renders of undecided rounds untouched for `CLEANUP_STALE_DAYS` (14, asked per round; resume re-renders), round folders that never finished ranking (logs only, an hour old), and `betasuite.log` past `CLEANUP_LOG_MAX_MB` (50, compressed to numbered `.gz` copies, `CLEANUP_KEEP_LOGS` 5 kept, emptied in place, skipped while written in the last 10 minutes). Never touches stats, caches, analysis runs, benchmark results or any round's record; never follows a symlink or leaves the output folder; unattended it removes nothing. In one measured output folder, renders were 29 GB of 29.5 GB. `ab_compare.sh` offers to delete a round's renders right after decide

- Suppression A/B proposes additions: each same-spot pair the bench suggests a rule for and no rule covers yet joins the proposed set at its suggested values, judged as its own change. Never a pair in the new `class_suppression_refused` list (per backend, `'label<-suppressor'`, validated, not in the censor key) and never one whose suppressor wins under 20% of its same-spot overlaps. `AB_ADDITIONS=0` (`--no-additions`) turns them off. `decide` prints the refused list with every addition the verdicts turned down. `betabench suppression` lists each unconfigured same-spot pair with what adding it would remove, and marks refused pairs
- `confirm_score` (per label, `default_confirm_score`): a track short of `min_track_hits` renders once one of its real detections scores at least this; off (None) by default, can only add boxes, validated, in the censor key only while set. auto_tune gains a `confirm_score` stage (0.5, 0.6, 0.7 against off, min_track_hits' confident-detection rule, skipped where min_track_hits is 1 everywhere, every change flagged for review) and ab_compare an experiment of the same name (auto_tune's value, else 0.5 per label)
- Near-duplicate videos: `bu_tuning.content_signature`, `same_content`, `near_duplicates` (runtime within 2%, every labelled-seconds figure within 6% or 2 s, at least 30 s labelled). `analyze_label_content.py` reports the pairs and how much footage they double, and marks each row's copies in `label_content.json`. The A/B ranking skips a copy of a video already chosen in the round or shown by an earlier one. A 56-video library held four such pairs (3.6 h of source)

- `tools/tuning/ab_compare.sh` (`ab_compare.py`, `ab_experiments.py`): A/B any change worth judging by eye on real footage. Experiments: `suppression`, `min_track_hits` and `match_distance` (from auto_tune's review values), `cut_bursts`, and `tracking` (any per-label setting via `AB_SET`). One command runs a whole round: a menu picks the experiment, then rank, explain, clip renders, a choice of what next (judge now, render the whole videos first, or stop), a wait while you fill in `feedback.csv`, decide (`chosen.json` plus the config lines to paste), and an offer of a confirm round of the chosen side on videos not yet judged. Judging waits again while `feedback.csv` has no verdicts, and every stop prints the `resume` line. `explain`, `decide` and `confirm` also run alone. `clips.md` and `feedback.csv` have one row per moment (one label, one stretch of time), so a clip where each side wins somewhere can be judged; a moment both sides censor with overlapping but different boxes is `both differ`. `explain` replaces a `feedback.csv` that has no verdicts and keeps one that has some. `AB_FOCUS=<label>` ranks and picks windows by one label's differences, in confirm rounds too. Per-label changes reach every profile that sets the key itself, and the lines printed say which profiles those are

### Fixed

- A feathered circle or ellipse rendered as a rounded square with hard straight edges. The feather blurred the shape mask with a reflecting border, which mirrored the mask at the box edge: alpha stayed at 0.95 up to all four sides and dropped to 0 in one pixel, and the heavier the feather the squarer it read (the breast blur variants, feather 0.25 to 0.55, on 220 to 330 px boxes). The border is now zeros. A `blur` also renders the ramp's outer half past its box (about two sigma, 51 px at feather 0.55 on a 300 px box, clipped at the frame), so coverage is not reduced and nothing is cut; `pixel` styles keep the ramp inside the box. Boxes, bars, stickers and unfeathered shapes are unchanged. Renders of a config with a feathered circle or ellipse blur or pixel style are made again (the censor key carries `feathered_shape_mask`); every other config keeps its key and its finished output
- `ProgressReporter.advance` lost counts when render workers called it together: it read the count under the lock, released it, and `update` wrote it back, so two workers could both write count+1 (the full suite once ended a 400-frame test at 177). The read, the add and the write are now one lock hold, so the "done, N" summary and the progress line are exact. `test_advance_loses_no_count_when_threads_switch_constantly` forces a thread switch every microsecond to make the race certain
- `auto_tune.py --apply` could not write a backend value once a structure profile held a block for the same label: `ConfigWriter.set_item_override` took the first `item_overrides` in the backend's text, which is a profile's, and `set_variant_item_override` took the profiles' `variants` for the model variants. The read-back caught both and restored the file, so nothing was written wrongly, but the write failed. Both now look only at the backend block's direct children
- `analyze_suppression_pairs.py` reported only its built-in list of pairs, so configured rules missing from it (the `nudenet_v3` vulva rules against `exposed_belly`, `exposed_breast` and `covered_breast`) were never shown. It now adds every pair a backend's `class_suppression` configures
- A preview could be served a shorter preview's caches and output. Preview names carried the start but not the length, so a 60-second preview after a 20-second one at the same start read the 20-second detection and person caches and had no detections past second 20: the rest of the slice was left uncensored (in reverse mode, untriggered), and with the 20-second output present the run skipped instead. Detection, person, shot-cut and output names now carry the length (`-preview+20.0s`, `-preview@600.0s+20.0s`), or `-preview+all` for a slice that reaches the end of the file, which every length of a short clip shares. Existing preview caches are not read by a run, so the first preview after updating detects again. The tuning and analysis tools predict the same names through one function (`preview_suffix_for_slice`), so their `--preview-seconds` must match the run's; with several lengths at one start, `--include-preview` reads the longest. `compare_effectiveness.py` gains `--preview-seconds` and now models a start past the end of the file or too late for the full window, both of which it named wrongly
- `run_all_analysis.sh` was killed by the kernel (exit 137) on a large library. Every cache-reading step parsed the whole library into dicts, about 500 bytes a detection (3.7 GB for 7.3 million), and the hub ran three at a time on a 15 GB machine. The steps now stream (see Changed), the hub admits parallel steps by memory, and a kill is reported with the memory it reached (see Added)
- The tracker broke ties by memory address: when two detections sat exactly as far from a track, the one at the lower address continued it, so the same detections could track differently from one run to the next, and a replay differently from the run it replayed. Ties now go to the detection earlier in the frame
- `analyze_jitter.py`, `analyze_track_breaks.py` and `analyze_style_flicker.py` rolled censor styles unseeded, and a style's padding moves box geometry, so two runs of the same analysis disagreed (by about 0.4% in style_flicker's resolve count). Every replay path (those three, `measure_replay`, `replay_rendered`) now seeds the rolls with the file hash, as a render does (`bu_track.seeded_styles`), so a replay rolls the styles the render rolled

- A render resumed from chunks an earlier run finished could change a censor's look at the chunk boundary: style rolls and sticker choices were unseeded, so the resumed run rolled them again. betatv now seeds them from the file's content hash, so the same file and settings always get the same looks and a resumed render matches an uninterrupted one. Re-rendering a file no longer re-rolls its styles; changing the style settings still does
- `validate_config` rejected NVENC presets: `encode_preset = 'p5'` with `encode_video_codec = 'h264_nvenc'` (what `betabench encode` recommends) failed as "not a known x264 preset". The preset (and `preview_encode_preset`) is now checked against the codec: x264's names always, `p1` to `p7` for NVENC codecs

NVENC now gets `encode_crf` as constant quality (`-cq`, `-b:v 0`) and x264 preset names translated to `p1`..`p7`. The libx264 command is byte-identical to before, pinned by a test

- Render workers came from the CPU count alone, so a 16-CPU laptop with 15 GiB of RAM got 8 workers for a 4096x2160 file and the kernel's out-of-memory killer killed betatv twice, about 25 frames per worker into the render (the GPU driver also failed an allocation and one chunk encoder segfaulted). The count is now also capped by `MemAvailable` and the frame size: `render_worker_mb_per_megapixel` (200 MB per megapixel per worker, a lower bound estimated from those two kills, which `tools/bench/tune_machine.sh` measures per machine; `None` turns the cap off) and `render_memory_reserve_mb` (2048, left for everything else). It applies to an explicit `render_workers` too, with a warning, and logs the numbers it used. Stats rows gain `render_memory_available_mb` and `render_memory_worker_cap`. `betabench encode` and `reverse` use the same count. Upgrade cost: high-resolution renders on machines short of memory use fewer workers, so they take longer and finish. Linux only; elsewhere the count stays CPU-based

Chunk encode, concat and final mux now capture ffmpeg's stderr (first 10 and last 30 lines) into the log at debug, and a failure names how ffmpeg ended, the frames written and the line naming the encoder (`ffmpeg exited 1 after 0 frame(s) written: [h264_nvenc @ ...] ...`). A signal is named instead of shown as a negative exit code: `ffmpeg crashed (SIGSEGV)`, `was killed (SIGKILL)`; a segfaulting ffmpeg prints nothing, so the signal is the whole reason. A successful ffmpeg that still printed at `-loglevel error` logs a warning. Upgrade cost: with `debug_mode` bit 1, ffmpeg's chatter now lands in the log at debug when each ffmpeg exits instead of streaming to the terminal (`--console-level debug` shows it). `betabench.ffmpeg_error_line` moved to `betautils_render`

- A last render chunk accepted short at the real end of the file (every MKV with a start offset, 2 or 3 frames) was re-rendered on every resume, because its recorded count never matched the plan. The verdict is now recorded and honoured, only for the last chunk and only for the plan it was made against. ## 1.3.0 (2026-10-06)

### Added

- `tools/bench/structure_survey.sh`: one command that measures every source file in `resources/uncensored_vids/` and the staging tree `resources/source/` and writes a reviewable `mv -n` script sorting them into profile folders. Three phases: whole-file shot-cut scans on the CPU, detection-only geometry slices on the GPU (asks first; runs when unattended), then the table and the script. Logs everything to `../output/benchmarks/structure_survey_<timestamp>/`, terminal filtered by `LOG_LEVEL`
- `betabench structure-scan`: whole-file shot-cut scans for every source file not yet scanned, files in parallel (one worker per core, at most 4; 2 workers ran 1.36x faster than 1 on a 2-core box). Written to the exact cache betatv's full run reads, so the real run finds its scan done. `--geometry-slices N` then runs detection without rendering on N 20-second slices spread through each file (25/50/75% for 3, never the start), which is what split-screen is recognised from
- With a declared profile (`--profile`, a path pattern or a source folder) betatv runs the shot-cut scan on a background thread alongside detection instead of in front of it. Same function, same cache, same cuts reach tracking; only the timing changes. The scan took 4m38s ahead of detection on a 35-minute file. A finished file with a declared profile also skips without scanning
- `betabench concurrency`: measures on your own machine what running the shot-cut scan alongside detection saves (scan alone, detection alone, both at once, after a warm-up, median of `--trials`), and structure-scan throughput at 1, 2, 4 and more workers with a recommended `--workers`. Every timing starts from an empty throwaway cache; nothing real is read or written. Worker counts above the number of files are reported as unmeasured, not timed (a pool of 8 given 3 files runs 3 processes, so the first version recommended 8 on noise), and the file count defaults to two per worker at the largest count
- After that background scan the run log says what measurement alone would have chosen, as a warning when that profile samples more densely than the declared one (a file in `compilation/` measuring as `quick_cut`: 9 fps instead of 18 means fewer detections on the shortest shots)

### Changed

- `covered_vulva` is promoted to `exposed_vulva` only when an `exposed_penis` is in frame. `exposed_vulva` and `exposed_anus` were evidence too, and on a 35-minute multi-subject file they drove 6,465 of 6,534 promotions, median about 7 box-sizes from the box they promoted, 98.5% touching no evidence at all: an exposed vulva in another pane or on another person was promoting a clothed crotch. Vulva censor boxes on that file fall 30% and their area 37%, while the moments carrying a vulva censor barely move. The censor key changes, so outputs re-render once; detection caches are untouched
- `betabench structure` works per source file, enumerated from disk across both trees, instead of per cache of one detection configuration. New columns say how much footage the timing rests on and whether it was the whole file or a slice, and how many sampled frames the geometry rests on. A file never scanned shows `?` and is never moved
- `--write-move-script` only scripts moves that pass every safety rule: whole-file timing evidence, never lowering the sample rate, never overriding a `manual_only` folder on timing alone unless the move raises the sample rate, and only from the tree root or a mapped folder. The rest are listed with the rule that held them back. Moves stay inside the tree their file is in
- The tuning replay (`auto_tune`) selects each video's profile the way a real run does: from the cached shot-cut scan through the same selector, with the folder convention applied, cuts passed to tracking, and the replayed detections' own sample rate
- File hashes are also memoised by inode, so moving a file (sorting, staging into `uncensored_vids/`, archiving to `completed/`) no longer re-reads it in full. One survey spent 4m39s re-hashing ~70 files after they were sorted. Analysis tools now persist the memo too; only betatv and betastare did, so every analyzer re-hashed archived files on every run
- `betabench` exits non-zero when a subcommand fails, and its log file defaults to `trace`. A harness wrapping it reported a failed phase as finished
- `betaconfig.py` comments cut to one-line headers; the rationale they carried is in CONFIG_REFERENCE.md. Every value is unchanged, so no cache key moves
- The shot-cut scan responds to Ctrl-C

### Fixed

- `tools/lib/python_env.sh` was excluded from git by the template `.gitignore`'s unanchored `lib/` rule, so on a fresh clone of 1.2.0 every shell script failed on its first line. The rule is anchored to the repo root and a test fails if any sourced file is missing or ignored
- A shot-cut scan that found zero cuts was treated the same as no scan at all: it logged `configured default (no shot-cut data)` and fell through to the default profile (13 of 56 files in one preview run), and betabench showed `n/a`. Zero cuts now measures as one shot over the whole window. The outcome only matched before because the shipped default is `scene`
- `betabench structure` divided by the time between the first and last censored detection instead of the footage scanned. A file whose boxes fell in one sampled frame scored 600,000,000 cuts a minute and was recommended for `quick-cut/`. It now uses the same window betatv selects with
- `betabench structure` never saw files sampled at a non-global rate: 8 of 56 in one survey, exactly the files the app had measured as `quick_cut`
- Preview slices at a non-zero offset handed tracking cut times on the scan's own timeline, so every cut fell before the slice's first detection and tracking matched straight across cuts. Full runs and offset-0 previews were unaffected. Existing offset-preview outputs are not re-rendered automatically, since no key changed
- A preview window running past the end of a short file counted the missing seconds in the structure denominator
- The test suite wrote into the real `../output/`: ~230 lines per run into a live `betasuite.log` and ~48 run-key records where betabench discovers configurations. Tests now get a throwaway output root, and a test fails if a new output path is added without it

## 1.2.0 (2026-10-06)

### Added

- Source folder convention: `profile_by_source_dir` maps a folder under `resources/uncensored_vids/` to a structure profile, so the folder a video sits in decides how it is censored. Ships with `scene/`, `compilation/`, `quick-cut/` and `split-screen/`. Deepest match wins, so a child folder overrides its parent; files in the root or in an unmapped folder are selected by measurement as before, which keeps the convention additive. Adding a folder is adding a line. Validated strictly, since every mistake here is a silent one: a key naming no variant, an empty key, one that normalises away to nothing, a `..`, a pasted absolute path, or two spellings of the same folder are all hard errors
- `compilation` profile, a fourth variant for sequential compilations where the subject changes every few seconds. Between `scene` and `quick_cut` on every axis. `manual_only`, because `short_shot_fraction` only counts sub-second shots and so cannot tell a compilation from a single scene
- `betabench structure` now recommends which source folder each file belongs in, alongside the measurements it already reported. It can identify split-screen, which no timing measure can: the spatial signals it already computes (simultaneous boxes, left-half share) are what separate panes from a quiet single scene. The quick-cut boundary is read from `betaconfig` so the recommendation cannot contradict what the app would select; the compilation and split-screen boundaries belong to the bench and are advisory, both read off small samples
- `betabench structure --write-move-script PATH` writes a reviewable shell script that sorts the source tree. Every move is `mv -n`, which never overwrites; each carries its measured reason as a comment; paths are shell-quoted; and it is safe to re-run. betabench never moves a file itself
- Duration-weighted shot shares in `betabench structure`: the share of RUNTIME in sub-1s and sub-10s shots, which is what the folder recommendation uses. A median shot length ranks real footage backwards, reporting a scene with one flurry of false cuts as the fastest-cutting file in a corpus
- `tools/lib/python_env.sh`: resolves the Python this repo should run, preferring its own `.venv` over whatever is on PATH, with `python_env_require` for a readable message when a dependency is missing
- The run log now names the rule that chose a profile, not just the profile: `structure profile: split_screen via source folder split-screen/ (...)`. Without it a folder key matching nothing on disk looks configured while quietly falling through to measurement

### Changed

- `profile_by_source_dir` is part of the censor key, so retuning the map does not serve back a render made under the old one. Because the shipped config sets the map, the censor key changes on upgrade and existing censored output is re-rendered once. Detection caches are unaffected, so the re-render does not re-run the model
- Every shell script uses `#!/bin/bash` rather than `#!/usr/bin/env bash`. On a system where `/usr/bin/env` is a uutils-coreutils multicall binary, running one through `env` failed with "Security violation: Requested utility ... does not match executable name"
- Every shell script resolves Python through `tools/lib/python_env.sh` instead of calling bare `python3` and relying on an activated venv. Bare `python3` silently runs the system interpreter under `sudo` or from a shell that never activated the venv, and silently runs a DIFFERENT project's packages when another venv is active

### Fixed

- `tune_nudenet_suppression.sh` looked for a venv at `../bin/activate`, the layout from before the venv moved inside the repo, so on any current checkout it always took the "no venv found" branch and ran against whatever `python3` was on PATH
- Quoting in `run_all_analysis.sh`'s step list, where an interpolated interpreter path would have broken the command string if it contained a space
