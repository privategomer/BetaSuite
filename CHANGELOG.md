# Changelog

This fork's releases. Versions follow [semantic versioning](https://semver.org/).

## Unreleased
### Added

- Suppression A/B proposes additions: each same-spot pair the bench suggests a rule for and no rule covers yet joins the proposed set at its suggested values, judged as its own change. Never a pair in the new `class_suppression_refused` list (per backend, `'label<-suppressor'`, validated, not in the censor key) and never one whose suppressor wins under 20% of its same-spot overlaps. `AB_ADDITIONS=0` (`--no-additions`) turns them off. `decide` prints the refused list with every addition the verdicts turned down. `betabench suppression` lists each unconfigured same-spot pair with what adding it would remove, and marks refused pairs
- `confirm_score` (per label, `default_confirm_score`): a track short of `min_track_hits` renders once one of its real detections scores at least this; off (None) by default, can only add boxes, validated, in the censor key only while set. auto_tune gains a `confirm_score` stage (0.5, 0.6, 0.7 against off, min_track_hits' confident-detection rule, skipped where min_track_hits is 1 everywhere, every change flagged for review) and ab_compare an experiment of the same name (auto_tune's value, else 0.5 per label)
- Near-duplicate videos: `bu_tuning.content_signature`, `same_content`, `near_duplicates` (runtime within 2%, every labelled-seconds figure within 6% or 2 s, at least 30 s labelled). `analyze_label_content.py` reports the pairs and how much footage they double, and marks each row's copies in `label_content.json`. The A/B ranking skips a copy of a video already chosen in the round or shown by an earlier one. The 2026-10-18 library holds four such pairs (3.6 h of source)

- `tools/tuning/ab_compare.sh` (`ab_compare.py`, `ab_experiments.py`): the suppression A/B generalised to any change worth judging by eye. Experiments: `suppression`, `min_track_hits` and `match_distance` (from auto_tune's review values), `cut_bursts`, and `tracking` (any per-label setting via `AB_SET`). One command runs a whole round: a menu picks the experiment, then rank, explain, clip renders, a wait while you fill in `feedback.csv`, decide (`chosen.json` plus the config lines to paste), and an offer of a confirm round of the chosen side on videos not yet judged. `explain`, `decide` and `confirm` also run alone. `AB_FOCUS=<label>` ranks and picks windows by one label's differences. Per-label changes reach every profile that sets the key itself, and the lines printed say which profiles those are
- `shot_cut_burst_window`, `shot_cut_burst_max_span`, `shot_cut_burst_keep`: merge bursts of shot cuts (fades, flashes) into one cut before tracking. Off by default (window 0). Every tracking path (runs and replays) goes through `bu_track.tracking_cut_times`; the structure profile is still chosen from the scanned cuts. Validated, and in the censor key only while on, so existing renders stay valid. The 2026-10-11 best variant (0.35 s, any span, keep first) censored 5,223 more confident detections for 841 more risky assignments over 56 videos
- `tools/analysis/analyze_label_content.py`, a `run_all_analysis.sh` step: per censored label, the videos with the most on-screen seconds of it, the most-leaning videos, and the most mixed seconds (two censored labels in one sample) with the pairs behind them. From the caches alone, at each cache's own rate (`bu_tuning.label_content`, `content_by_video`)
- auto_tune flags values only eyes can settle: `decisions.json` gains `review`, `key` and `label`. A `min_track_hits` change is always flagged (the confident-score metric cannot see misfires above 0.5); a loosening stage that kept its value flags a tighter one that removes at least one ambiguous decision per reset it adds at no coverage loss (`bu_tuning.tightening_review`). The summary lists them with the A/B command
- `betabench cache` (structure, geometry, hysteresis, suppression, dedup) and `betabench hardware` (render, decode, detect); `all` is both
- `harness_lib.sh`: `choose_option` (numbered menu, default when unattended) and `wait_for_enter` (waits while a person does something, gives up when unattended)
- `ab_compare.sh resume [DIR]` (DIR a path or just the folder name; `--help` prints the whole header): picks a round up from its first unfinished step (explain, clips, the judge-or-render choice, decide, the confirm offer), read from the round's folder (`ab_compare.py --status DIR`). Renders take `--skip-existing`: finished files are kept, a video with every file present is not replayed, and a half-rendered whole video resumes from its chunks. The side-by-side is written beside its final name and moved into place, so a killed stack never leaves a half file that looks finished. A status it cannot read stops the resume with that reason instead of reading as "nothing done"

- Measure a predictable subset of the library instead of all of it: `betabench --first-videos N` (first N files by name, case-insensitive, across every folder and both source trees) or `--videos-per-folder N` (first N by name in each directory; `uncensored_vids/scene` and `source/scene` are two). Applies to `structure`, `structure-scan`, `concurrency`, `encode` and `reverse`, and the chosen files are listed in the log. `structure_survey.sh` and `reverse_cost.sh` take it as `VIDEOS_FIRST=N` / `VIDEOS_PER_FOLDER=N`, passed to every phase, and print the list to the terminal. Neither set means every file, as before
- `betabench reverse` and `tools/bench/reverse_cost.sh`: phase 0 of reverse mode, measured before any of it is built. Times each candidate frame style over a whole real frame through the real renderers (blur triple_box/box/gaussian, mosaic, hex, solid), window blends at typical and large sizes, a censored window and the fade blend; runs the real render pipeline (real chunk encode command, real worker count) with and without a triggered frame layer on the same footage, reporting both speed and encoded size; and weights the difference by the share of each file's runtime a trigger would hold on, from whole-file detection caches of the selected backend. Reports a speedup as a speedup rather than flooring it at zero. Reads only; encodes go to a removed scratch folder. Not part of `all`. `_run_segments` gains an optional per-frame hook for this; without it, behaviour is unchanged
- `betabench encode`: render encode speed and quality per encoder on your own machine. Pipes the same stretch of the highest-resolution source through the real chunk encode command with the real worker count, once per encoder (current x264 settings, `faster` and `veryfast`, NVENC at cq 17/19/21/23 and `p7` when the GPU opens NVENC sessions), scores every output against the source (SSIM and PSNR on luma), times decoding alone as the ceiling, and names the fastest encoder within 0.25 dB of the current quality. Past full renders at the same resolution, from the stats log, turn the speedup into a real-render estimate. Probes how many NVENC sessions open at once and says if `render_workers` must come down. Not part of `all`
- `tools/tuning/suppression_ab.sh` (`suppression_ab.py`): A/B two `class_suppression` sets on real footage. Replays every cached video under the current rules and a proposed set (by default `betabench suppression`'s suggestions: configured pairs retuned or dropped, never added; `AB_PROPOSED=rules.json` for any other), ranks videos by box-seconds censored under one set and not the other, and renders the top `AB_VIDEOS` (2) at the `AB_CLIPS` (6) windows where they differ most: outlines (grey both, orange current only, magenta proposed only) and the real censor side by side (current left, proposed right). `AB_FULL=1` renders the chosen videos whole. Writes `ranking.json`; reads caches only
- `tools/analysis/analyze_cut_bursts.py`, a `run_all_analysis.sh` step: replays the caches with bursts of shot cuts (fades, flashes) merged to one cut, per profile, and reports confident detections restored against risky track assignments added. Measurement only; nothing merges bursts in a run
- `bu_tuning.measure_replay` reports confident-detection coverage per label (detections scoring at least 0.5 that no rendered box of their label covers), and takes a `cut_transform` for what-if cuts
- `bu_cache.videos_across_sample_rates`: one configuration's videos at every sample rate a profile can select. The two new tools rank 18 fps quick-cut caches too; the older analysers still read the global rate only
- `bu_tuning.replay_rendered`, `item_overrides_in_effect` and `class_suppression_in_effect`: one production replay and two restore-on-exit config patches for the replay tools

### Changed

- `run_all_analysis.sh` timing steps are opt-in: `--with-encode`, `--with-reverse`, `--with-hardware` (decode/detect/render timing and the no-approximation render), or `--with-timing` for all three. A default run reads caches only (`betabench cache` in place of `betabench all`); `--quick` is accepted and does nothing. The run writes `moves.sh` (the structure survey's reviewable source-folder moves), `label_content.json` and `analyze_cut_bursts.json`, and ends with where each recommendation is
- `suppression_ab.sh` / `suppression_ab.py` are the suppression experiment of `ab_compare`, with every mode and env var as before plus `confirm`. `decide` writes `chosen.json` beside `chosen_rules.json`, and the next round is `ab_compare.sh confirm` instead of an `AB_PROPOSED` path
- A/B `clips.md` and `feedback.csv` have one row per moment (one label, one stretch of time) instead of one per label, side and cause with every span in it, so a clip where each side wins somewhere can be judged. A moment both sides censor with overlapping but different boxes is `both differ` ("both censor, boxes differ"); it used to show as two rows, LEFT only and RIGHT only, at the same time. `explain` replaces a `feedback.csv` that has no verdicts and keeps one that has some
- An A/B round asks what to do once the clips are rendered (judge now, render the whole videos first, or stop) instead of offering the whole-video renders before judging. A terminal closing during hours of whole-video renders used to strand the verdict step; now judging comes first, waits again while `feedback.csv` has no verdicts, and every stop prints the `resume` line
- `analyze_cut_bursts.py` measures every variant against the cuts as scanned whatever the config says, prints the best one as config lines, and with `--json` writes it for the `cut_bursts` experiment
- `measure_replay` takes `cut_bursts` (None follows the config, False the scanned cuts); a `cut_transform` replaces the configured merge rather than stacking on it

- `min_track_hits` is 2 for every label again (it was 3 for `nudenet_v3` `exposed_breast`, `exposed_vulva` and `covered_vulva`, and `retinanet_v2` `exposed_breast`, all raised by auto_tune). At 3 the 2026-10-09 run withheld 23,311 breast and 11,405 vulva boxes that 1 would have drawn. Changes the censor key: re-rendering a file reuses its detections
- `auto_tune.py` `min_track_hits` stage: tries 1 to 4 with no cap and recommends the strictest value that leaves no more than `--max-confident-loss` (0.1%) of the label's confident detections (score at least `--confident-score`, 0.5) uncensored beyond the fewest any value leaves. It used to count every dropped box as noise removed, which is how it raised 2 to 3. It can now recommend above or below the current value; nothing is written without `--apply`

- Sticker censors cache their resized, cropped and feathered planes and blend premultiplied colour, which is the same float32 arithmetic in the same order, so output is byte-identical. On a 400px box with feather 0.25 a sticker went from 18.8 ms to 1.2 ms per frame while its size holds (the render holds each track's size steady), measured on one core in the cloud workspace. The cache is LRU, capped at 192 MB

- `run_all_analysis.sh` can run `betabench encode` and `betabench reverse` (now opt-in, see above). Both measure wall clock and throughput, so they run one at a time after the parallel analysis batch has finished and before `auto_tune`, rather than in the batch, where up to two other CPU-bound steps would be measured with them

- Tracking replays log to a silent logger. One analysis pass on 2026-10-10 wrote about 3,800 per-video tracking lines into the production `betasuite.log`. `smooth_boxes` takes a `logger`, and `prepare_boxes_for_render` passes its own through
- Every logger is built by `betautils_log` (`tool_logger` for a tool's file and terminal, `silent_logger` for replays and workers), with one TRACE level. `betabench`, `auto_tune`, `diagnose_style_variety`, `clean_run_both_backends`, the replay logger and the scan worker each built their own plain logger and re-declared TRACE. Standalone setup and release tools, which import no pipeline module, keep their own. A test fails if anything else builds a logger
- `suppression_ab.sh` says which rule made each difference and turns your verdicts into rules. `explain` writes `clips.md` (every difference in each clip: time in the clip, side, the rule that caused it, what the proposed set does to that rule) and `feedback.csv` (one verdict per row); `_diff.mp4` outlines carry the rule under the label. `decide` tallies verdicts per rule, keeps each changed rule on the side its verdicts favour (ties and silence keep the current rule) and writes `chosen_rules.json` for the next round. Attribution comes from a new `on_suppressed` tracking-observer event, so it is the production rule's decision, not a copy of it
- `suppression_ab.sh` skips the whole-video renders when the clip renders failed, since they render the same way; `AB_FULL=1` still forces them

### Fixed

- `ab_compare.sh confirm` ignored `AB_FOCUS`: the confirm round always took the earlier round's focus. `AB_FOCUS` now replaces it
- `validate_config` rejected NVENC presets: `encode_preset = 'p5'` with `encode_video_codec = 'h264_nvenc'` (what `betabench encode` recommends) failed as "not a known x264 preset". The preset (and `preview_encode_preset`) is now checked against the codec: x264's names always, `p1` to `p7` for NVENC codecs
- The test suite inherited the user's encoder: with `h264_nvenc` in `betaconfig.py`, 41 end-to-end render tests needed a free GPU session and failed without one. `tests/__init__.py` pins x264 for the suite; encoder tests set their own
- `analyze_track_breaks.py` and `analyze_jitter.py` ignored shot cuts when classifying a new track, while the tracker never continues across one, so every new shot's first detection beside where the last shot's track ended counted as an "unexplained" reset or a "likely reset". Both now share the tracker's test (`bu_track.cut_separates`): track_breaks reports those as `after-cut`, and jitter counts them apart from likely resets. On the 2026-10-18 run "unexplained" was the largest breast bucket (28,875)
- The A/B side-by-side passed `-crf` to the configured encoder, which NVENC ignores, falling back to its default bitrate. It now uses the render's own encoder arguments (`bu_render.encoder_options`: `-cq` and the NVENC preset for NVENC)

- `betabench` cache-reading sections warned "no cached detections found for any configuration" whenever they had no rows to report, so `dedup` with one picture size sent people looking for caches that were there. The warning now fires only when no cache loaded

- `betabench suppression` paired boxes across videos: grouping was by timestamp alone, so on 56 videos `exposed_breast<-face_femme` counted 6.3M "overlaps" against 49k real ones, and every suggestion was fitted to them. Pairs are now formed within a video. `min_iou` is suggested at the valley between the side-by-side and same-spot clusters instead of the 25th percentile (which sits inside the side-by-side cluster), `margin` from the same-spot pairs, and pairs with no same-spot cluster get no suggestion. A new table runs each configured rule through the production suppression function, as configured and as suggested, with the share of removals that sat side by side (each removal credited to the one rule that made it, as production does). The cross-size dedup section had the same grouping bug
- `betabench all` measured every cache-reading section twice: a preview configuration re-read the real caches, so the `[PREVIEW]` sections repeated the real ones under another label. Each configuration now reads only its own caches
- `analyze_track_breaks.py`, `analyze_jitter.py` and `analyze_style_flicker.py` replayed tracking with no structure profile, no shot cuts, no class promotion and no geometry filter, so their numbers described a configuration no real run uses (vulva tracks replayed with a 43.2 s gap that every profile overrides to 4 or 8 s). They now feed tracking exactly what a run does (`bu_track.prepare_tracking_inputs`) under each file's own profile and cuts (`bu_tuning.replay_tracking_context`), and the track-break sweeps scale a profile's own value along with the backend's
- `auto_tune.py` replayed candidates for keys every file's profile overrides: on 2026-10-09 it spent 12 minutes on six identical `exposed_breast` `track_max_gap` replays. A stage whose key every file's profile sets is now skipped with the profile values listed, and a partly masked one says how many files ignore it

- `run_all_analysis.sh`: `betabench_all` and `betabench_render_noapprox` launch together in the parallel batch, and betabench names its output folder after the current second, so both wrote to the same folder: one `results.json` overwrote the other and both appended to one interleaved `betabench.log` (the console output in each step's own log was unaffected). Every betabench step now gets its own `--out-dir` under the analysis run's folder, so its results sit next to the rest of that run
- `run_all_analysis.sh --help` printed only lines 2 to 52, stopping partway through the list of steps. It now prints the whole header, however long it gets

- `encode_video_codec = 'h264_nvenc'` ignored `encode_crf` without an error (NVENC has no `-crf`) and encoded at NVENC's default bitrate, and an x264 preset such as preview's `ultrafast` failed the encode. NVENC now gets `encode_crf` as constant quality (`-cq`, `-b:v 0`) and x264 preset names translated to `p1`..`p7`. The libx264 command is byte-identical to before, pinned by a test

- A last render chunk accepted short at the real end of the file (every MKV with a start offset, 2 or 3 frames) was re-rendered on every resume, because its recorded count never matched the plan. The verdict is now recorded and honoured, only for the last chunk and only for the plan it was made against. The routine case logs at debug instead of warning; a shortfall over one second of frames still warns

- `compare_effectiveness.py` could not start: it imported `replay_tune` from another folder, and passed the preview suffix where the backend name goes. It now runs, through the production pipeline, with `--backend`
- `replay_tune.py` wrote `item_overrides` variants to the shared tier, which any backend, variant or profile value for the same key overrides, so those variants replayed the baseline while reporting a difference. Each key now lands on every tier that would shadow it. `--backend` also resolved picture sizes for the previously selected backend
- `replay_tune.py` and `analyze_span_merge.py` rebuilt suppression, box conversion and tracking by hand, without promotion, the geometry filter, shot cuts or the file's profile. Both replay through the production pipeline now
- `smooth_boxes`' per-label "min_track_hits dropped N" debug line reported the running total across labels, so every label after the first was credited with the ones before it
- `suppression_ab.py` renders failed on every chunk: its logger came from `betabench.build_logger`, a plain logger without `trace()`, which the render path calls. Its test had used a stand-in logger that had `trace()`, so it passed
- `suppression_ab.py` paired boxes greedily, so each sample's box took its neighbour's and every track left one spurious box on each side: identical renders differed by 9%. It now asks whether the other set censors the same spot at an overlapping time. The pairing was also quadratic: one split-screen video took ten minutes and the rank phase 67. Time-bucketed, 217k boxes compare in under 3 seconds

## 1.3.0 (2026-10-06)

### Added

- `tools/bench/structure_survey.sh`: one command that measures every source file in `resources/uncensored_vids/` and the staging tree `resources/source/` and writes a reviewable `mv -n` script sorting them into profile folders. Three phases: whole-file shot-cut scans on the CPU, detection-only geometry slices on the GPU (asks first; runs when unattended), then the table and the script. Logs everything to `../output/benchmarks/structure_survey_<timestamp>/`, terminal filtered by `LOG_LEVEL`
- `betabench structure-scan`: whole-file shot-cut scans for every source file not yet scanned, files in parallel (one worker per core, at most 4; 2 workers ran 1.36x faster than 1 on a 2-core box). Written to the exact cache betatv's full run reads, so the real run finds its scan done. `--geometry-slices N` then runs detection without rendering on N 20-second slices spread through each file (25/50/75% for 3, never the start), which is what split-screen is recognised from
- With a declared profile (`--profile`, a path pattern or a source folder) betatv runs the shot-cut scan on a background thread alongside detection instead of in front of it. Same function, same cache, same cuts reach tracking; only the timing changes. The scan took 4m38s ahead of detection on a 35-minute file. A finished file with a declared profile also skips without scanning
- `betabench concurrency`: measures on your own machine what running the shot-cut scan alongside detection saves (scan alone, detection alone, both at once, after a warm-up, median of `--trials`), and structure-scan throughput at 1, 2, 4 and more workers with a recommended `--workers`. Every timing starts from an empty throwaway cache; nothing real is read or written. Worker counts above the number of files are reported as unmeasured, not timed (a pool of 8 given 3 files runs 3 processes, so the first version recommended 8 on noise), and the file count defaults to two per worker at the largest count
- After that background scan the run log says what measurement alone would have chosen, as a warning when that profile samples more densely than the declared one (a file in `compilation/` measuring as `quick_cut`: 9 fps instead of 18 means fewer detections on the shortest shots)

### Changed

- `covered_vulva` is promoted to `exposed_vulva` only when an `exposed_penis` is in frame. `exposed_vulva` and `exposed_anus` were evidence too, and on a 35-minute multi-subject file they drove 6,465 of 6,534 promotions, median about 7 box-sizes from the box they promoted, 98.5% touching no evidence at all: an exposed vulva in another pane or on another person was promoting a clothed crotch. Vulva censor boxes on that file fall 30% and their area 37%, while the moments carrying a vulva censor barely move. The censor key changes, so outputs re-render once; detection caches are untouched
- `betabench structure` works per source file, enumerated from disk across both trees, instead of per cache of one detection configuration. New columns say how much footage the timing rests on and whether it was the whole file or a slice, and how many sampled frames the geometry rests on. A file never scanned shows `?` and is never moved
- `--write-move-script` only scripts moves that pass every safety rule: whole-file timing evidence, never lowering the sample rate, never overriding a `manual_only` folder on timing alone unless the move raises the sample rate, and only from the tree root or a mapped folder. The rest are listed with the rule that held them back. Moves stay inside the tree their file is in
- The tuning replay (`auto_tune`) selects each video's profile the way a real run does: from the cached shot-cut scan through the same selector, with the folder convention applied, cuts passed to tracking, and the replayed detections' own sample rate
- File hashes are also memoised by inode, so moving a file (sorting, staging into `uncensored_vids/`, archiving to `completed/`) no longer re-reads it in full. One survey spent 4m39s re-hashing ~70 files after they were sorted. Analysis tools now persist the memo too; only betatv and betastare did, so every analyzer re-hashed archived files on every run
- `betabench` exits non-zero when a subcommand fails, and its log file defaults to `trace`. A harness wrapping it reported a failed phase as finished
- `betaconfig.py` comments cut to one-line headers; the rationale they carried is in CONFIG_REFERENCE.md. Every value is unchanged, so no cache key moves
- The shot-cut scan responds to Ctrl-C

### Fixed

- `tools/lib/python_env.sh` was excluded from git by the template `.gitignore`'s unanchored `lib/` rule, so on a fresh clone of 1.2.0 every shell script failed on its first line. The rule is anchored to the repo root and a test fails if any sourced file is missing or ignored
- A shot-cut scan that found zero cuts was treated the same as no scan at all: it logged `configured default (no shot-cut data)` and fell through to the default profile (13 of 56 files in one preview run), and betabench showed `n/a`. Zero cuts now measures as one shot over the whole window. The outcome only matched before because the shipped default is `scene`
- `betabench structure` divided by the time between the first and last censored detection instead of the footage scanned. A file whose boxes fell in one sampled frame scored 600,000,000 cuts a minute and was recommended for `quick-cut/`. It now uses the same window betatv selects with
- `betabench structure` never saw files sampled at a non-global rate: 8 of 56 in one survey, exactly the files the app had measured as `quick_cut`
- Preview slices at a non-zero offset handed tracking cut times on the scan's own timeline, so every cut fell before the slice's first detection and tracking matched straight across cuts. Full runs and offset-0 previews were unaffected. Existing offset-preview outputs are not re-rendered automatically, since no key changed
- A preview window running past the end of a short file counted the missing seconds in the structure denominator
- The test suite wrote into the real `../output/`: ~230 lines per run into a live `betasuite.log` and ~48 run-key records where betabench discovers configurations. Tests now get a throwaway output root, and a test fails if a new output path is added without it

## 1.2.0 (2026-10-06)

### Added

- Source folder convention: `profile_by_source_dir` maps a folder under `resources/uncensored_vids/` to a structure profile, so the folder a video sits in decides how it is censored. Ships with `scene/`, `compilation/`, `quick-cut/` and `split-screen/`. Deepest match wins, so a child folder overrides its parent; files in the root or in an unmapped folder are selected by measurement as before, which keeps the convention additive. Adding a folder is adding a line. Validated strictly, since every mistake here is a silent one: a key naming no variant, an empty key, one that normalises away to nothing, a `..`, a pasted absolute path, or two spellings of the same folder are all hard errors
- `compilation` profile, a fourth variant for sequential compilations where the subject changes every few seconds. Between `scene` and `quick_cut` on every axis. `manual_only`, because `short_shot_fraction` only counts sub-second shots and so cannot tell a compilation from a single scene
- `betabench structure` now recommends which source folder each file belongs in, alongside the measurements it already reported. It can identify split-screen, which no timing measure can: the spatial signals it already computes (simultaneous boxes, left-half share) are what separate panes from a quiet single scene. The quick-cut boundary is read from `betaconfig` so the recommendation cannot contradict what the app would select; the compilation and split-screen boundaries belong to the bench and are advisory, both read off small samples
- `betabench structure --write-move-script PATH` writes a reviewable shell script that sorts the source tree. Every move is `mv -n`, which never overwrites; each carries its measured reason as a comment; paths are shell-quoted; and it is safe to re-run. betabench never moves a file itself
- Duration-weighted shot shares in `betabench structure`: the share of RUNTIME in sub-1s and sub-10s shots, which is what the folder recommendation uses. A median shot length ranks real footage backwards, reporting a scene with one flurry of false cuts as the fastest-cutting file in a corpus
- `tools/lib/python_env.sh`: resolves the Python this repo should run, preferring its own `.venv` over whatever is on PATH, with `python_env_require` for a readable message when a dependency is missing
- The run log now names the rule that chose a profile, not just the profile: `structure profile: split_screen via source folder split-screen/ (...)`. Without it a folder key matching nothing on disk looks configured while quietly falling through to measurement

### Changed

- `profile_by_source_dir` is part of the censor key, so retuning the map does not serve back a render made under the old one. Because the shipped config sets the map, the censor key changes on upgrade and existing censored output is re-rendered once. Detection caches are unaffected, so the re-render does not re-run the model
- Every shell script uses `#!/bin/bash` rather than `#!/usr/bin/env bash`. On a system where `/usr/bin/env` is a uutils-coreutils multicall binary, running one through `env` failed with "Security violation: Requested utility ... does not match executable name"
- Every shell script resolves Python through `tools/lib/python_env.sh` instead of calling bare `python3` and relying on an activated venv. Bare `python3` silently runs the system interpreter under `sudo` or from a shell that never activated the venv, and silently runs a DIFFERENT project's packages when another venv is active

### Fixed

- `tune_nudenet_suppression.sh` looked for a venv at `../bin/activate`, the layout from before the venv moved inside the repo, so on any current checkout it always took the "no venv found" branch and ran against whatever `python3` was on PATH
- Quoting in `run_all_analysis.sh`'s step list, where an interpolated interpreter path would have broken the command string if it contained a space

## 1.1.0 (2026-10-03)

### Added

- `SETUP.md`: full setup guide for Linux and Windows, scripted and manual, plus migration notes for upstream 0.2.4 users
- `setup.sh` (Linux) and `setup.cmd` / `setup.ps1` (Windows): one-shot, re-runnable setup. Installs the pinned Python with uv, creates `.venv`, installs the GPU or CPU build, creates the `resources/` and `output/` folders, downloads models, aligns `gpu_enabled`, and verifies the result. Logs everything to `setup.log`
- `tools/setup/fetch_models.py`: downloads the 320n model from the hash-pinned `nudenet` package on PyPI and checks every model present; anything that isn't a real ONNX file (such as a saved GitHub sign-in page) is moved aside instead of trusted. 640m and RetinaNet are manual downloads (GitHub serves them only to signed-in users), with direct links in `SETUP.md`
- `tools/setup/verify_env.py`: checks Python, packages, ffmpeg, folders, and that each model loads on the expected execution provider
- Versioning: a `VERSION` file, `--version` on every entry point, and the version in BetaTV's startup log line and in each stats row (`betasuite_version`). Checkouts that aren't exactly on a release tag report semver build metadata, e.g. `1.1.0+3.g1a2b3c4.dirty`
- `tools/release/release.py`: suggests a version bump from the commits since the last tag, bumps `VERSION` with the `semver` package, dates the CHANGELOG entry, runs the tests, commits, tags, and optionally pushes and creates the GitHub release
- `requirements.txt`, `requirements-cpu.txt`, `requirements-gpu.txt`, `requirements-vision-windows.txt`, `requirements-dev.txt`, and `.python-version` (3.12)
